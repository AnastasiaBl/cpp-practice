# Object-Oriented Programming and Extended Euclidean Algorithm

Учебный проект на C++, посвящённый применению объектно-ориентированного программирования для реализации математических алгоритмов, рекурсивных функций и расширенного алгоритма Евклида.

## Цель проекта

Закрепить принципы объектно-ориентированного программирования, научиться организовывать вычислительные задачи с помощью классов и методов, а также реализовать расширенный алгоритм Евклида для нахождения обратного элемента по модулю.

## Реализованные задачи

### 1. Рекурсивные функции в ООП

Вычислительные функции из предыдущей лабораторной работы перенесены в отдельные классы. Для первых трёх задач методы объявлены в секции `public`.

**Класс `Task_1` — факториал**

Метод `factorial(int n)` рекурсивно вычисляет факториал числа.

\[
n! = n \cdot (n-1)!
\]

**Класс `Task_2` — числа Трибоначчи**

Метод `tribonacci(int n)` рекурсивно вычисляет элементы последовательности Трибоначчи:

\[
T(n)=T(n-1)+T(n-2)+T(n-3)
\]

Начальные значения: T(0) = 0, T(1) = 1, T(2) = 1.

**Класс `Task_3` — алгоритм Евклида**

Метод `gcd(int a, int b)` рекурсивно вычисляет наибольший общий делитель двух чисел.

\[
НОД(a,b)=НОД(b,a \bmod b)
\]

### 2. Расширенный алгоритм Евклида

Класс `Task_4` реализует расширенный алгоритм Евклида.

Вычислительный метод `extended_Euc(int a, int b, int& x)` находится в секции `private`, поэтому вызывается только из публичного метода класса.

Алгоритм позволяет найти коэффициенты линейного представления НОД:

\[
НОД(a,b)=a \cdot x+b \cdot y
\]

При этом в текущей реализации вычисляется только коэффициент `x`, соответствующий первому аргументу `a`.

Для вычисления обратного элемента по модулю используется условие:

\[
НОД(a,m)=1
\]

Если условие выполняется, обратный элемент вычисляется по формуле:

\[
a^{-1}\bmod m=(x\bmod m+m)\bmod m
\]

**Контрольный пример:**

Найти обратный элемент числа 13 по модулю 131:

\[
13^{-1}\bmod 131=121
\]

Проверка:

\[
13\cdot121=1573=12\cdot131+1
\]

Следовательно, результат — 121.

Для этого примера аргументы должны передаваться в следующем порядке: `a = 13`, `b = 131`.

## Структура программы

- `Check` — проверка корректности вводимых целых чисел.
- `Task_1` — класс для вычисления факториала.
- `Task_2` — класс для вычисления чисел Трибоначчи.
- `Task_3` — класс для вычисления НОД.
- `Task_4` — класс расширенного алгоритма Евклида.
- `ADD` — главное меню и управление работой программы.
- `main()` — точка входа в программу.

## Принципы ООП

- **Классы и объекты:** каждая вычислительная задача представлена отдельным классом.
- **Инкапсуляция:** метод расширенного алгоритма Евклида объявлен как `private`, а пользовательский интерфейс задачи — как `public`.
- **Разделение ответственности:** ввод данных, вычисления и управление меню распределены между отдельными классами.

## Ограничения текущей реализации

- В расширенном алгоритме вычисляется только коэффициент `x`; коэффициент `y` не рассчитывается и не выводится.
- Переменная `P` в методе `extended_Euc()` не используется.
- Для вычисления обратного элемента необходимо передавать число первым аргументом, а модуль — вторым.
- При вводе второго аргумента `b = 0` возможна операция деления по модулю нуля в выражении вычисления обратного элемента.
- В классах `Task_1` и `Task_2` используется рекурсивный ввод данных, а вычисление Трибоначчи имеет экспоненциальную временную сложность.
- В программе используются глобальные переменные `num` и `i`, что создаёт общую изменяемую область состояния.
- Управление повторным запуском программы реализовано через рекурсивные вызовы `start()` и `clos()`, что может приводить к накоплению вызовов в стеке.
- При некорректном выборе пункта меню сообщение об ошибке указывает диапазон от 1 до 3, хотя предусмотрено четыре задачи.
